# RadarML Lite — Track B: radar modulation classification

**1st place, Synapson Datathon (IEEE), September 2026.** Classifying radar
pulses into seven modulation families — `barker`, `cw`, `fmcw`, `fsk`, `hyp`,
`nlfm`, `quad` — across 13 signal-to-noise ratios from +30 dB down to −30 dB,
on waveforms recorded over the air with University College London's ARESTOR
RFSoC platform.

My code only. **The dataset is not redistributed here** and neither is the
organisers' starter code — see [Provenance](#provenance).

---

## The result I am most pleased with is the one I threw away

I built two pipelines. The one that scored higher is not the one I submitted.

| | Validation balanced accuracy | Audit set | Submitted? |
|---|---|---|---|
| Coherent Fourier template bank | **0.9962** | 0.9965 (137,280 samples) | **no** |
| Compact complex-STFT neural net | 0.9202 | 0.9204 | **yes** |

A 7.6-point gap, and I shipped the worse number on purpose. Here is the
per-SNR profile of the template bank, which is what gave it away:

| SNR | −30 | −25 | −20 | −15 | −10 | −5 | 0 | +5 | +10 | +15 | +20 | +25 | +30 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| balanced acc. | 0.951 | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** |

**A perfect 1.0000 at −25 dB is not a good score. It is a physically
implausible one.** At −25 dB the signal sits far below the noise floor; no
classifier reading only a permitted signal representation should separate seven
modulation families flawlessly there. Something other than modulation was being
recognised.

It was. `rejected-template-bank/fit_report.json` records what the thing
actually built:

```json
{ "source_pulses": 52800, "templates": 660, "median_phase_lock": 0.9999994 }
```

**660 templates — exactly the number of waveform configurations in the
dataset.** The bank averages the clean 30 dB pulses of each configuration into
one complex template, then matches a test pulse against all 660 coherently.
And because the SNR variants are generated by adding noise to *the same*
recorded pulses — the dataset README is explicit that "noise variants are not
additional independent captures" — coherent integration over 16,800 complex
samples delivers enough processing gain to recover *which recording this is*,
no matter how much noise was layered on top. A `phase_lock` of 0.9999994
is the signature of that: near-perfect coherence against a stored copy of the
same waveform.

So it was not classifying modulation. It was re-identifying source pulses and
reading the label off the match. On the supplied validation split that is worth
99.6%. On a genuinely new recording from the same seven families it is worth
very little, because there would be no stored template to lock onto. It also
sits against the event rules, which require model inputs to be "permitted
signal representations and fixed acquisition constants, never filenames, IDs,
source metadata" and say plainly: *do not recover test labels by matching
signals to the public archive.*

**A memorising model that scores 99.6% is a worse model than a learning one
that scores 92%.** The whole code is kept here in
`rejected-template-bank/` rather than deleted, because the finding is the
interesting part and because a reviewer should be able to check my reasoning
instead of taking it from me.

## What was submitted

A compact complex-STFT classifier, trained from random initialisation — no
pretrained weights, no external data, as the rules required.

**Representation.** An explicit two-sided complex STFT: 256 frequency bins ×
66 time frames, 256-sample rectangular windows, non-overlapping blocks, right
zero-padding. The deliberate choice is keeping the **complex** spectrum rather
than collapsing to a power spectrogram. Modulation families are distinguished
by how phase evolves — linear chirp in `fmcw`, non-linear in `nlfm`, discrete
hops in `fsk`, a binary code in `barker` — and a magnitude-only spectrogram
throws that away. So a phase-sensitive learned projection (rank 64) runs
alongside a small power-STFT CNN, and the two are combined.

**Training against noise, not around it.** Class-balanced sampling over source
pulses, all 13 noise levels introduced after a two-epoch warm-up, with
`hard_snr_weight: 2.0` to put extra weight on the low-SNR end. Each batch
carries a clean/noisy *pair* of the same pulse under two losses: cross-entropy
on both, and a feature-consistency term pulling their internal representations
together (`feature_consistency_weight: 2.0`, nearly an order of magnitude above
the clean-loss weight of 0.25). The intent is a representation that is stable
under noise, rather than one that memorises clean pulses and degrades.

**Checkpoint selection on validation only**, comparing raw against an EMA copy
(`ema_decay: 0.999`), with the blind test never touched during development —
the model freeze happened before the test package was released.

Full configuration in `submission/training_config.json`; seed 42, 80 epochs,
105,600 samples per epoch, batch 256, AdamW at 1e-3.

## Reproducing it

You will need the dataset, which is UCL's and is **not** in this repository:
[RadarML Lite on UCL's research data repository](https://rdr.ucl.ac.uk/articles/dataset/Radar_ML_-_Lite/33977674)
(660 waveform configurations, 66,000 pulses, 16,800 complex samples per pulse
at 120 MS/s, ~2.54 GB compressed).

Trained model checkpoints are also excluded — 797 `.pt` files totalling about
107 MB, which do not belong in git.
